# AstroCam

Захват с UVC-вебкамер (сделано и проверено на Microsoft LifeCam Studio) для стекинга: Луна, планеты, звёзды, таймлапсы.
Windows, Python 3.10+ (tkinter, numpy, Pillow), ffmpeg.

```
AstroCam.cmd              запуск (pythonw astrocam.py)
astrocam.py               приложение
camctl.exe / camctl\      управление камерой через DirectShow (выдержка, фокус, баланс белого…); build.cmd пересобирает
go2rtc_ctl.ps1            забрать камеру у go2rtc и вернуть её (elevated, через UAC)
presets\*.json            ваши пресеты; settings.json — последнее состояние
```

## Что умеет

* **Камера**: выбор устройства, потока (RAW YUY2 / MJPEG), разрешения и fps из реального списка режимов камеры.
  Ручные настройки ползунками **прямо во время превью**: выдержка (у LifeCam от 1/8000 до 1 с), фокус, баланс белого,
  резкость, яркость, контраст, цифровой зум/пан. Кнопка «Астро-база» — резкость 0, без компенсации засветки, всё вручную.
  «Зафиксировать авто» — камера сама подбирает выдержку, фокус и баланс белого, потом значения замораживаются (для дневной съёмки).
* **Лучшие кадры из записи** — сортирует кадры SER/AVI/MP4 по резкости и сохраняет N лучших в PNG (для движущихся объектов).
  Настройки сохраняются в пресет и применяются перед каждой записью.
* **Съёмка**: длительность и/или число кадров (что наступит раньше), пропуск первых N кадров (пока камера применяет выдержку),
  сохранение каждого N-го кадра (таймлапс), серии с паузами (для дерротации в WinJUPOS).
* **Кроп**: выделение мышью на превью, точные X/Y/Ш/В, быстрые размеры, «на яркий объект».
  Для SER — **ведение кропа за объектом**: компенсирует уход планеты/Луны по кадру без монтировки.
* **Превью**: авто-растяжка только для отображения (данные не трогаются), гистограмма, максимум/пересвет,
  метрика резкости для фокусировки, увеличенный центр кропа.
* **Форматы**:

| Формат | Для чего |
|---|---|
| SER моно (Y) / цвет | AutoStakkert!, Siril, PIPP — основной формат. Пишется напрямую, с UTC-меткой каждого кадра |
| AVI несжатый | то же, если программа не читает SER |
| MKV FFV1 | без потерь, ~в 2 раза меньше; цвет хранится в родном 4:2:2 камеры — для архива |
| MP4 H.264 / H.265 | обычное видео/таймлапс: CPU x264/x265, Intel QSV, NVIDIA NVENC; режим «качество (CRF/CQ)» или «битрейт» |
| TIFF / PNG / FITS / JPEG кадры | DeepSkyStacker (TIFF), Siril (FITS) |
| MJPEG как есть | 1080p30 без перекодирования (то, что отдаёт камера) |

* Имя файла по шаблону: `{target} {utc} {date} {time} {fmt} {size} {exp} {n}`. `{utc}` — середина записи в стиле WinJUPOS
  (`2026-11-16-0230_5`). Рядом пишется `.txt` с параметрами съёмки (камера, кроп, выдержка, время начала/середины/конца, реальный fps, потери).
* **go2rtc**: если камеру держит go2rtc (Frigate), приложение после подтверждения UAC закомментирует в `C:\go2rtc\go2rtc.yaml`
  только потоки этой камеры и перезапустит go2rtc; остальные камеры продолжают работать. Оригинал — `go2rtc.yaml.astrocam-orig`,
  при выходе приложение предложит вернуть. Вручную:
  `Start-Process pwsh -Verb RunAs -ArgumentList '-File','C:\AstroCam\go2rtc_ctl.ps1','-Action','restore'`

## Сырые кадры — стоит ли

Да. YUY2 — это несжатые 8 бит, где яркость Y хранится в полном разрешении (цвет — в половинном по горизонтали).
«Моно Y» из RAW — честная яркость каждого пикселя без блоков MJPEG и без цветовой интерполяции, втрое меньше данных, чем RGB.
Это лучший вариант для Луны и звёзд. Для цветных планет — SER «Цвет».
Плата — USB 2.0: 1920×1080 только 5 к/с, 1280×720 — 10 к/с. Для планет с маленьким кропом выгоднее 720p@10 + кроп.

Особенности LifeCam:
* выдержка задаётся степенями двойки (2⁻¹³…2⁰ с); при 5 к/с кадр длится 200 мс — для звёзд это практический максимум;
* резкость камеры ставьте 0 — иначе ореолы вокруг звёзд и края Луны, которые стекинг потом усиливает;
* RAW отдаёт «ТВ-диапазон» 16–235 — опция «Растянуть 16–235 → 0–255» есть, но для стекинга не обязательна.

## Днём: «сверхразрешение» удалённого объекта

Идея та же, что у планет: сотни кадров одного и того же статичного объекта. Воздух дрожит, камера чуть вибрирует —
каждый кадр немного смазан по-своему и сдвинут на доли пикселя. Стекинг выбирает лучшие участки лучших кадров,
усредняет шум, а drizzle использует субпиксельные сдвиги, чтобы собрать картинку с бо́льшим разрешением.

Пресеты «День — сверхразрешение, цвет / моно Y»:
1. Запустите превью, выделите кроп вокруг объекта (здание, вывеска, антенна, кран). Кроп — это только экономия места:
   разрешение он не прибавляет. Цифровой зум камеры не используйте — он просто интерполирует.
2. «Зафиксировать авто» (вкладка «Камера») — камера сама подберёт фокус, выдержку и баланс белого, и они замрут.
   Иначе между кадрами будут плавать яркость и фокус, а стекинг этого не любит.
3. Фокус подстройте ползунком по показателю «резкость» под превью (он считается по кропу). Выдержку уменьшите на 1–2 шага,
   если на гистограмме не пропадают тени: чем короче, тем меньше смаз от марева над асфальтом.
4. 300–1000 кадров (при 5 к/с — 1–3 минуты). Камеру ничем не трогайте, лучше снимать через открытое окно:
   стекло (особенно двойное) даёт двоение и мыло, которое стекинг не уберёт.

Чего ждать: реально — примерно в 1,5 раза больше деталей и намного меньше шума, чем на одном кадре. Чудес из 1080p-вебкамеры
с широкоугольником не будет: если объект на одном кадре занимает 10 пикселей, после стекинга будет условно 15 чётких.

Движущееся (машины, люди): стекать нельзя — объект смажется или исчезнет. Пресет «День — движущиеся объекты»
пишет MJPEG 30 к/с без перекодирования; потом «Лучшие кадры из записи…» (вкладка «Вывод») отсортирует кадры
по резкости и сохранит лучшие в PNG — выбираете глазами.

## Что делать с кадрами дальше

Все программы бесплатные, под Windows.

### AutoStakkert! — главный инструмент (Луна, планеты, днём — здания)

1. *Open* → ваш `.ser` (или `.avi`).
2. Режим: **Surface** — для Луны и дневных сцен, **Planet (COG)** — для маленькой планеты на тёмном фоне.
   *Image Stabilization* оставить включённым. Нажать **1) Analyse** — построится график качества кадров.
3. *Stack Options*: **Number of frames to stack** — 10–25 % лучших (из 300 кадров ≈ 50–75; при сильном мареве — меньше).
   Формат вывода TIF. Для сверхразрешения включить **Drizzle 1.5x** (3x почти всегда только шумит).
   *Sharpened* можно отметить, чтобы сразу получить и подшарпленную версию для оценки.
4. *Alignment points*: размер AP 50–100 для дневных сцен и Луны, 25–50 для планет; **Place AP grid**.
   Точки должны лежать на деталях, а не на ровном небе.
5. **3) Stack**. Результат — в папке `AS_P…` рядом с исходником.

### Повышение резкости

Сложенный кадр всегда выглядит мягким — так и должно быть, вся резкость «спрятана» в нём.
* **RegiStax 6** → *Wavelets*: открыть TIF, двигать первые 2–3 слайдера (layer 1–2 сильнее, 3 слабее), *Denoise* 0.1–0.2
  на первом слое, чтобы не вылез шум. *Do all* → *Save image*.
* Или **ImPPG** / **Siril** (*Обработка → Деконволюция* или *Вейвлеты*) — то же самое другими средствами.
* Меру держите: ореолы вокруг контрастных краёв = перебор.

### Планеты дополнительно
* Несколько роликов по 60–120 с (серии в AstroCam) → каждый в AutoStakkert → **WinJUPOS** *De-rotation of images*
  складывает их с учётом вращения Юпитера. Время берётся из имени файла `{utc}`.
* **PIPP** — если нужно что-то конвертировать, обрезать или центрировать перед AutoStakkert.

### Звёзды и туманности
* **DeepSkyStacker**: TIFF-кадры → *Open picture files*; без отдельных dark-кадров тоже работает, но лучше снять
  20–30 кадров с закрытым объективом той же выдержкой (папка darks) и добавить как *Dark files*.
  *Check all* → *Register checked pictures* → *Stack*. Результат растягивать кривыми в любом редакторе.
* **Siril**: SER или FITS → *Регистрация* (по звёздам) → *Сложение* (сигма-клиппинг) → *Растяжка гистограммы*.
  Для Луны и дневных сцен Siril тоже может (*Регистрация → глобальная, по изображению*), но AutoStakkert проще и лучше.

### Быстрый ориентир по объёмам
| Сцена | Кадров снять | Сложить |
|---|---|---|
| Луна, днём здания | 300–1000 | 15–25 % |
| Планета | 3–6 серий по 60–120 с | 10–20 % каждой серии |
| Звёзды | 100–300 + 20–30 darks | 70–90 % |
